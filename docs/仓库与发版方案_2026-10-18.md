## 二、三个方案

### 方案 A（推荐）：开发仓不动，新建「试玩仓」只放发布物

```
fangguoge-game   ← 继续开发（源码 + 美术 + 历史，268MB，一行都不用动）
fangguoge-demo   ← 新建 public：README + 截图 + CHANGELOG，下载全走 Releases
```

- 试玩仓**不放源码**，只放：`README.md`（简介/截图/操作/致谢）、`CHANGELOG.md`、`screenshots/`；
  每一版挂一个 Release（`fangguoge-demo-v1.4.0-win64.zip`）。
- **优点**：开发仓的测试脚本/半成品不外露；不会出现两份源码分叉；秋招给这一个链接即可。
- **代价**：每次发版多一步"往试玩仓发 Release"（我可以写一个 `release.bat` 一键做：导出 → 压 zip → 算 SHA256 → 建 Release → 删旧包）。

### 方案 B：复制一份完整源码当「封版仓」

- 新建仓库，把当前源码推一份上去（不带历史）。
- **优点**：一个链接既是下载也是代码。
- **代价**：**两份源码**，以后修 bug 要改两遍；268 MB 再翻一倍。**不推荐**，除非你打算"这版封死，不再改"。

### 方案 C：原仓库归档只读 + 新仓库继续开发

- 所有旧 Release 链接、star、题目里的跳转全失效，历史断裂。**不推荐**。

## 四、这次发版要做的动作（确认后执行）

1. **导出**：Godot 4.7.2 mono 导出 Windows Desktop → `fangguoge-demo.exe`（约 287MB，5–10 分钟）
2. **实测**：先本地跑一遍导出包（隔空启动 → 进主菜单 → 退出），确认不是"导出能成、跑起来崩"
3. **打包**：exe + `说明.txt`（操作/配置/致谢）压成 zip，算 SHA256
4. **建 Release**：开发仓或试玩仓（按你选的方案）发 `v1.4.0`，正文写清本轮改动（我已有完整 CHANGELOG）
5. **删旧**：确认新包能跑之后，再删旧 Release（`gh release delete <tag> --yes --cleanup-tag`）
6. **收尾**：试玩仓 README 更新"最新版本 + 下载链接 + 对应 commit"

> ⚠️ 顺序很重要：**先验新包，再删旧包**。287MB 的包删了要重新导出很麻烦。
