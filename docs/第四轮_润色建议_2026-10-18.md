## 1. 台球：加"认输"，并说清胜负的影响

### 现状（查过代码）

- 台球局目前**没有退出/认输入口**，只能一杆杆打完（或卡住时被迫关游戏）。
- 胜负的唯一去处：`BilliardGame.EndGame()` → `GameManager.RecordChoice("ch09_billiard", result)`
  → 只进**结束页的「选择回顾」**（`data/text/demo_review.json` 里有一条 `ch09_billiard`）。
- **对剧情、好感、勇气值、后续对白：零影响。** 三套点评（win / lose / tie）只是台词不同。
- 也就是说：现在"赢了"和"输了"的区别，只体现在那句点评 + 结束页的一行回顾上。

### 建议方案

**A. 认输入口（推荐做法）**

- 台球界面底部右侧（"返回菜单"左边）加一个低调文字按钮 **「认输」**，字号 18、半透明；
- 点击 → 一个轻确认（"这局就算了？"）→ 直接按"输"结算：走 `EndGame(1, meWin:false)` → 江洁那句 lose 点评 → `Closed` → 接 `table_done`，剧情照常往下走。
- 台词建议加一句过渡（避免突兀）：
  > 我：「……不打了。」
  > 江洁：「行啊。反正这局你也追不上了。」（笑）
- 顺带把「返回菜单」在台球里的问题一起修（见第 2 条）。

**B. 胜负的影响（建议"轻量但有存在感"）**

| 选项 | 效果 | 说明 |
|---|---|---|
| **B1（推荐）** | 赢：勇气 +2；输：不变；平：各 +1 | 一行数值，不改变剧情分支，但"赢一局"有实感 |
| B2 | 赢：江洁的好感 +1（如果她在这场有数值线） | 需要确认这一章是否给江洁记好感 |
| B3 | 只改台词（现状 + 认输），不加数值 | 最保守 |

> 我倾向 **B1**：让"赢"稍微有回报，但绝不因为输赢卡剧情或改结局走向——这章讲的是"和她相处"，不是"必须赢"。

**C. 工作量**：认输按钮 + 确认框 + 一句过渡台词，约 ★（半小时）；B1 的数值 ★。

## 2. 台球里点「返回菜单」没反应 + 全场景返回自检

### 现状（查过代码）

- 台球打开时会 `DialogueManager.SetUiSuppressed(true)`，并把 `BackButton / BagButton` 的 `ZIndex` 抬到 100
  （`BilliardGame.SetCornerButtonsRaised`），**目的是让按钮浮在台面遮罩上方**。
- 但从你的截图看：按钮画在上面、点了却没反应。可能是**画得上去、点不进去**（全屏台面控件先吃掉了点击），
  也可能是**确认框弹了但被压在下面**。
- 结论：**不能只靠 ZIndex**。同类全屏模态（手机、背包、台球）都有这个隐患。

### 建议方案

1. **统一"模态里的返回"规则**：
   - 打开状态（台球/手机/背包/对话框）时，**Esc 或按钮 = 先关模态**，再按一次才弹"返回菜单"确认；
   - 把 `BackButton` / `BagButton` 从 `ZIndex` 改成**挂在 CanvasLayer(85) 上**（比模态高、比确认框 90 低），
     既画得上也一定点得到。
2. **写一个"全场景返回自检"驱动**（我在本地跑，不入库）：
   逐章进入 → 点一次返回 → 断言出现确认框 → 点"确定" → 断言回到主菜单；
   再单独测"台球中 / 手机中 / 背包中"三种模态下的返回。
3. 结果会给你一张表：**14 章 × 3 种模态 = 42 项**，哪一项不通我逐个修。

**工作量**：★（改层级 + 一个 Esc 分支）+ ★（自检驱动一次性）

## 4. 骑行：摩托是个小剪影、路两侧空

### 现状

- 骑手/摩托是**程序绘制的一张很小的剪影**（约 40×50），贴在路面中央，和背景的水彩完全不搭；
- 路面两侧是**纯色块**（你看的两个蓝框），一条路孤零零悬在中间；
- 背景上半部分其实画了电线杆和天空，**下半部分完全没画**。

### 建议方案（按投入从低到高）

**A. 只修"人车"（★）**
- 生成/绘制一张"骑手背影 + 踏板摩托"的水彩贴图（约 140×180，带一点风吹衣服的动感），
  替换现在的剪影；加 2px 上下颠簸 + 转弯时轻微倾斜。
- 立刻解决"最突兀"的那一点。

**B. 给路两侧加景（★★，推荐与 A 一起做）**
- 用 2~3 张**横向可循环的景带**（草地 / 稻田 / 护栏 / 路肩石），按速度横向滚动，远近两层做视差；
- 颜色统一压到和背景同一套灰绿/土黄，低饱和；
- 每 20~30 秒掠过一块**路牌**（"×× 12km"）或**里程碑**，让"往南"有进度感。

**C. 路面质感（★）**
- 现在路面是纯灰渐变；加水彩纸纹 + 车道线轻微抖动 + 远处热浪，成本很低。

> 需要你点头的：**A/B/C 里的贴图要我用 AI 生成（每次 5–10 积分）还是手绘风程序画？**
> 程序画零积分但质感有限；AI 生成更贴水彩，但要做透明底与色调匹配。

**工作量**：A ★ / A+B ★★★

## 5. 有些章节"些许卡"

### 现状

没有测量数据，只能从代码里列嫌疑：

| 嫌疑 | 位置 | 为什么 |
|---|---|---|
| **台球每帧整台重绘** | `BilliardGame._Process` → `board.QueueRedraw()` | 台面 + 16 颗球 + 阴影 + 瞄准线全量重画，1906×932 下最费 |
| **骑行每帧画道路** | `RideTrack._Draw` | 大量 `DrawLine`/多边形，帧率不稳时会更明显 |
| **雨窗 / 火星子 / 心刃等逐帧特效** | `RainWindow`、`EmberDust`、`HeartBlades`、`BalconyNight` | 各自 `QueueRedraw`，叠加时吃 CPU 绘制 |
| **对话打字机 + 提示呼吸 Tween** | `DialogueBox` / `ChapterBase` | 文本重排 + 每帧 tween，通常不致命 |

### 建议

1. **先量再改**：加一个 F3 性能叠层（帧时间 ms / FPS / 绘制节点数），我跑一遍 14 章，
   给你一张"每章平均帧时间 + 最差帧"的表，**用数据指名哪一章哪一段卡**。
2. 按数据优化，优先级：
   - 台球：只在"有变化"时重绘（静止时跳过），预计省 60% 绘制；
   - 骑行：降低远景线条细分 + 远景贴图化；
   - 特效：给逐帧重绘的节点加"可见才更新"的开关。
3. 另外可加一个**低配开关**（设置页）：关掉逐帧特效/降低重绘频率，给老机器兜底。

**工作量**：测量 ★ / 优化 ★★
